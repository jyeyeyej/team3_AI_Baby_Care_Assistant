# AI 육아 도우미 프론트엔드 개발 계획서

> Streamlit과 FastAPI를 연결하는 0~36개월 영유아 보호자용 테스트 서비스의 화면·상태·연동 계획입니다.

## 1. 목표와 구현 원칙

- 기술 스택은 Python, Streamlit, FastAPI HTTP API이며 모바일에서 보기 쉬운 한 열 중심 레이아웃으로 구현합니다.
- 실제 회원가입·JWT·푸시 알림은 구현하지 않습니다. 준비된 테스트 사용자를 선택해 로그인합니다.
- `st.session_state`에는 화면 상태와 식별자만 보관하고, 아기·기록·알림의 기준 데이터는 항상 FastAPI에서 다시 조회합니다.
- 모든 시각은 화면에서 `Asia/Seoul`로 표시하고, 입력한 날짜·시간은 사용자가 이해하기 쉬운 한국어 형식으로 보여 줍니다.
- 의료 관련 답변은 진단처럼 표현하지 않으며 출처, 확인 시점, 방문 전 전화 확인 또는 의료기관 상담 안내를 함께 표시합니다.
- 네트워크 요청 중에는 해당 버튼을 잠그고 진행 표시를 보여 중복 저장을 예방합니다.

## 2. 정보 구조와 화면 흐름

로그인 전에는 시작 화면만 노출합니다. 로그인 후 아기가 없으면 내 정보 화면의 등록 폼으로, 있으면 홈으로 이동합니다.

```text
시작·테스트 로그인
  └─ 아기 없음 → 내 정보의 아기 등록 → 홈
  └─ 아기 있음 → 홈

홈 ↔ AI 육아 도우미 ↔ 육아 관리 ↔ 내 정보
                   └─ 생활 기록 / 성장 / 예방접종
```

상단에는 선택된 아기 이름과 생후 개월 수를 표시하고, 메뉴는 다음 네 항목으로 고정합니다.

1. 홈
2. AI 육아 도우미
3. 육아 관리
4. 내 정보

## 3. 화면별 상세 계획

### 3.1 시작·테스트 로그인

- 테스트 사용자 카드 또는 선택 상자를 제공하고 `POST /api/test-login`을 호출합니다.
- 응답의 `user_id`, `baby_id`, `session_id`를 세션에 저장합니다.
- 아기가 없는 사용자는 아기 기본정보 등록 폼으로 보냅니다.
- 비밀번호, 회원가입, 로그아웃 이력 관리 기능은 범위에서 제외합니다.

### 3.2 아기 정보 등록·수정 (`profile_page.py`)

- 입력: 이름 또는 애칭, 생년월일, 성별, 수유 방식(모유·분유·혼합), 선택 항목인 몸무게·키·알레르기입니다.
- 등록은 `POST /api/babies`, 수정은 `PATCH /api/babies/{baby_id}`를 사용합니다.
- 미래 생년월일, 0 이하 성장 수치, 필수값 누락은 저장 전에 바로 안내합니다.
- 알레르기는 칩 형태로 추가·삭제할 수 있게 하고, 저장 전 변경 내용을 요약한 확인 영역을 표시합니다.

### 3.3 홈

홈은 한 화면에서 오늘 필요한 행동을 확인하는 요약 대시보드입니다.

- 수유 알림 카드: `GET /api/reminders/feeding/{baby_id}` 결과를 표시합니다.
- 최근 생활 카드: 마지막 수유·최근 수면·최근 배변을 보여 주고 육아 관리로 연결합니다.
- 성장 요약: 최근 키·몸무게와 간단한 추세를 표시하고 성장 탭으로 연결합니다.
- 다음 예방접종: 다음 접종명·차수·예정일을 표시합니다.
- 월령별 가이드: AI 육아 도우미로 바로 질문할 수 있는 예시 질문을 제공합니다.

수유 알림의 행동은 아래처럼 통일합니다.

| 사용자 행동 | 화면 처리 | API |
| --- | --- | --- |
| 수유했어요 | 수유 빠른 기록 폼을 열고 저장 후 홈을 새로고침 | `POST /api/care-logs` |
| 10분 후 | 10분 뒤 다시 보일 상태로 변경 | `PATCH /api/reminders/{reminder_id}` (`snooze`) |
| 건너뛰기 | 기록을 만들지 않고 설정 간격 뒤 다시 알림 | `PATCH /api/reminders/{reminder_id}` (`skip`) |

`confirm`은 알림 확인 상태 변경에만 사용하며, 실제 수유 기록은 별도 저장 요청으로 남깁니다. 홈과 채팅 화면은 같은 알림 조회 함수를 사용해 일관된 상태를 표시합니다.

### 3.4 AI 육아 도우미

- 상단: 아기 이름, 월령, 수유 방식, 등록된 알레르기 요약과 홈과 동일한 수유 알림 카드
- 본문: 사용자·AI 말풍선, 답변 종류별 결과 카드, 자동 스크롤되는 채팅 영역
- 입력: 텍스트 입력, 전송 버튼, 음성 파일 업로드, 기저귀 사진 업로드
- 빠른 기록: 수유·수면·배변·성장 버튼

텍스트 채팅은 기본적으로 `POST /api/chat/stream`을 사용합니다. SSE 이벤트 `received`, `loading_context`, `analyzing_request`, `using_tool`, `generating_answer`, `completed`, `error`를 사람이 읽을 수 있는 진행 문구로 전환합니다. 스트리밍을 사용할 수 없는 경우에는 `POST /api/chat`으로 폴백합니다.

응답의 `response_type`에 따라 UI를 분기합니다.

| 응답 유형 | 표시 방식 |
| --- | --- |
| `text`, `out_of_scope`, `unsupported_feature`, `clarification_required`, `policy_blocked`, `error` | 일반 답변 카드와 필요한 다음 행동 |
| `options` | 선택 버튼 또는 선택 상자 |
| `record_confirmation` | 추출된 기록 내용을 확인하는 카드 |
| `hospital_list` | 병원명·주소·전화·확인 시점 카드 목록 |
| `diaper_analysis` | 관찰 결과, 위험 신호, 출처, 저장 선택 카드 |
| `speech_transcription` | STT 텍스트와 수정 입력칸 |
| `stt_record_approval` | 승인·수정·취소 버튼이 있는 고정 승인 카드 |

RAG 답변에는 맞춤 정보(월령·수유 방식·알레르기 반영 여부), 근거 문서 제목·발행기관·확인일·링크, `high`/`low` 신뢰도를 표시합니다. 근거가 부족하면 일반 지식으로 채우지 않고 정보 부족 안내를 표시합니다.

병원 검색은 현재 위치를 요청하거나 사용하지 않습니다. 지역명 입력란과 `pediatric`/`emergency` 선택을 제공해 `GET /api/hospitals/search`를 호출하며, 결과마다 방문 전 전화 확인 문구를 붙입니다.

### 3.5 빠른 생활 기록

빠른 기록은 채팅을 거치지 않고 구조화된 UI 입력으로 `POST /api/care-logs`를 호출하며 `input_source="ui"`를 전송합니다. UI·텍스트 기록은 백엔드 정책상 별도 승인 없이 저장됩니다.

| 기록 | 입력 항목 | 핵심 검증 |
| --- | --- | --- |
| 수유 | 방식, 수유량(선택), 시각 | 수유량 0 이상, 미수유 표현은 기록 생성 안 함 |
| 수면 | 시작 또는 종료, 시각 | 중복 시작·시작 없는 종료 오류 표시 |
| 배변 | 소변/대변, 색상·형태·메모(선택), 시각 | 소변·대변 중 하나 이상 |
| 성장 | 몸무게·키·머리둘레, 측정 시각 | 하나 이상 입력, 모든 값 0 초과 |

저장 성공 시 토스트와 함께 홈의 최근 기록·알림, 생활 기록 목록을 무효화하여 다음 렌더링에서 다시 조회합니다. 화면에서 만든 `idempotency_key`는 처리 중인 동일 요청에 유지합니다.

### 3.6 음성 기록 승인

1. MP3, WAV, M4A, WebM 파일과 최대 20MB 제한을 업로드 전 안내하고 검증합니다.
2. STT 텍스트와 추출된 기록 항목을 보여 줍니다.
3. 실제 기록일 때만 승인 카드에서 승인·수정·취소를 선택하게 합니다.
4. 승인은 백엔드가 반환한 `tool_call_id`와 세션 식별자로 처리하고, 브라우저가 수정한 기록 인자를 다시 신뢰하도록 보내지 않습니다.
5. 승인 완료·거절·10분 만료·중복 클릭 결과를 각각 분명히 표시합니다.

"먹이려고 했는데 안 먹었어"처럼 미수유를 뜻하는 STT는 기록이나 승인 카드로 만들지 않고, 저장되지 않았음을 안내합니다.

### 3.7 기저귀 사진 분석

- 지원 형식과 최대 10MB, 원본 사진이 영구 저장되지 않는다는 안내를 업로드 영역에 표시합니다.
- 분석 버튼은 `POST /api/images/diaper-analysis`를 호출하고, 처리 중에는 재실행을 막습니다.
- 결과는 관찰 가능한 색·형태·묽기, 위험 신호 안내, 참고 출처로 나누어 보여 줍니다.
- 분석 자체는 진단이 아니며 기록 저장은 별도 선택입니다. 저장을 선택하면 배변 기록 폼에 구조화된 값만 채워 주고, 보호자가 확인한 후 `POST /api/care-logs`로 저장합니다.
- 위험 신호가 있으면 병원 검색으로 연결하고 응급 상황에는 119 안내를 우선합니다.

### 3.8 육아 관리 (`care_page.py`)

`st.tabs`로 생활 기록과 성장을 구성합니다.

- 생활 기록: 오늘/기간 필터, 수유·수면·배변·성장 유형 필터, 목록, 최근 7일 패턴 요약. `GET /api/care-logs`, `GET /api/care-patterns/{baby_id}?days=7`을 사용합니다.
- 기록 수정·삭제: 수정은 `PATCH /api/care-logs/{log_id}`, 삭제는 `DELETE /api/care-logs/{log_id}`. 두 동작 모두 대상·변경값을 확인하는 다이얼로그를 거칩니다.
- 성장: `GET /api/growth/{baby_id}` 기반 키·몸무게·머리둘레 그래프와 월령·성별 참고값을 함께 표시합니다. 정상·비정상 판정이나 진단 표현을 쓰지 않습니다.
패턴 데이터가 부족하면 빈 차트나 임의의 평균 대신 "기록이 더 쌓이면 평균과 변화를 알려드릴게요" 안내와 빠른 기록 버튼을 표시합니다.

### 3.9 예방접종 (`vaccination_page.py`)

- `GET /api/vaccinations/{baby_id}`로 완료 내역, 다음 접종명·차수·예정일을 표시합니다.
- 실제 의료 기록이 아닌 테스트 데이터임을 화면 상단에 명시합니다.
- 홈의 다음 예방접종 카드와 동일한 데이터를 사용하고, 상세 확인은 이 페이지로 연결합니다.

### 3.10 내 정보 (`profile_page.py`)

- 보호자 테스트 계정 정보는 읽기 전용으로 표시합니다.
- 아기 프로필과 알레르기, 수유 방식, 현재 성장 수치, 수유 알림 간격을 보여 줍니다.
- 아기 수정과 알림 설정 변경은 각각의 저장 버튼과 성공·실패 피드백을 둡니다.

## 4. 프론트엔드 구조

```text
frontend/
├─ app.py                 # 앱 시작, 로그인 여부별 라우팅
├─ api.py                 # FastAPI 요청, SSE 파서, 공통 오류 변환
├─ common.py              # 세션 초기화, 시간/응답 포맷, 알림 카드
└─ pages/
   ├─ login_page.py
   ├─ home_page.py
   ├─ chat_page.py
   ├─ care_page.py
   ├─ vaccination_page.py
   └─ profile_page.py
```

`common.py`는 네비게이션, 아기 요약, 수유 알림 카드, 입력 검증 및 공통 상태 화면을 제공합니다. `api.py`는 모든 요청에 공통 헤더·타임아웃·오류 처리를 적용하고, `{success, message, data, request_id}` 응답을 하나의 결과 객체로 정규화합니다. 각 페이지 파일에는 HTTP 세부 구현을 두지 않습니다.

## 5. 세션·데이터 상태 계약

필수 세션 상태는 아래로 제한합니다.

```python
st.session_state.update({
    "user_id": None,
    "baby_id": None,
    "session_id": None,
    "selected_menu": "홈",
    "pending_stt_tool_call_id": None,
    "chat_messages": [],
    "request_in_progress": False,
})
```

- `chat_messages`는 현재 화면 렌더링을 위한 표시용 캐시입니다. 대화의 기준 상태는 백엔드 Redis이며, 과거 채팅 검색 기능은 만들지 않습니다.
- 저장·수정·삭제·알림 변경 성공 뒤에는 해당 목록과 홈 요약을 다시 요청합니다.
- 테스트 사용자나 아기가 바뀌면 아기별 캐시, 채팅 표시, 승인 대기 상태를 모두 초기화합니다.
- 세션 만료 또는 소유권 오류가 오면 민감 정보를 남기지 않고 로그인 화면으로 이동합니다.

## 6. 공통 상태·오류 UX

| 상태 | 화면 처리 |
| --- | --- |
| 로딩 | Spinner, 버튼 잠금, 채팅은 SSE 진행 문구 표시 |
| 빈 데이터 | 원인 설명과 다음 행동 버튼 |
| 입력 오류(422) | 해당 필드 가까이에 검증 문구 표시 |
| 인증·세션 오류 | 로그인 재시작 안내 |
| 승인 만료·불일치 | 저장 없이 다시 음성 입력 또는 요청 안내 |
| MCP·RAG·외부 API 오류 | 추측 없이 일시적 오류와 재시도 안내 |
| 병원 결과 없음 | 정상적인 빈 결과로 지역명 확인 요청 |
| 위험 신호 | 일반 카드보다 눈에 띄는 안전 안내와 병원/119 행동 제공 |

오류 메시지에 API 키, 내부 URL, SQL, 스택 트레이스는 표시하지 않습니다. 화면에는 `request_id`를 "문의 시 참고 번호"로만 제공해 문제 추적에 활용합니다.

## 7. 구현 순서와 완료 기준

1. 앱 골격, 테스트 로그인, 세션 초기화, 공통 API 클라이언트
2. 아기 등록·수정과 홈 요약·수유 알림
3. 빠른 생활 기록과 생활 기록 조회·수정·삭제
